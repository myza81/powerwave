# Powerwave Sample Disturbance Files

This directory holds reusable sample disturbance recordings for development,
testing, and demonstration. Files here are shared across sessions so that
Claude Code and developers do not need to re-upload or re-describe data.

---

## Directory Structure

```
samples/
├── comtrade/          COMTRADE recordings — flat layout
│   ├── <event_id>.cfg
│   └── <event_id>.dat
├── csv/               Operational CSV time-series (one file per event)
│   └── <event_id>.csv
├── excel/             Operational Excel files (one file per event)
│   └── <event_id>.xlsx
└── manifests/         Pre-built YAML event manifests
    └── <event_id>.yaml
```

Files sit directly in `comtrade/` (not in per-event subdirectories).
Pairs are identified by matching stem: `pulu_20260306.cfg` + `pulu_20260306.dat`.

---

## Naming Convention

All sample events use the following identifier format:

```
<location>_<YYYYMMDD>
```

Examples:
- `pulu_20260306`  — Pulu substation event, 6 March 2026
- `setiawangsa_20251118`  — Setiawangsa substation event, 18 Nov 2025

Event identifiers are lowercase, alphanumeric + underscore only.

---

## Manifests

A manifest is a YAML file in `manifests/` that describes a single disturbance
event across all its sources (COMTRADE + CSV + Excel). Manifests capture:

- Source paths (repository-relative)
- Detected start/trigger times
- Sampling rates
- Time-alignment offsets between sources

Manifests are generated by `tools/build_event_manifest.py` and can be loaded
directly into a `MultiSourceSession` (see Task 6 integration hook in D3.1).

**Never hardcode temporary upload paths or user-specific paths in manifests.**
All paths in manifests are repository-relative from the project root.

## Inspection Tools

Use these scripts from the project root to inspect sample files:

### COMTRADE Inspector
```
python tools/inspect_comtrade.py samples/comtrade/<event_id>.cfg
python tools/inspect_comtrade.py samples/comtrade/<event_id>.cfg --json
```

### CSV Time-Series Inspector
```
python tools/inspect_csv_timeseries.py samples/csv/<event_id>.csv
python tools/inspect_csv_timeseries.py samples/csv/<event_id>.csv --json
```

### Manifest Builder
```
python tools/build_event_manifest.py \
  --event-id <event_id> \
  --comtrade samples/comtrade/<event_id>.cfg \
  --csv samples/csv/<event_id>.csv \
  --output samples/manifests/<event_id>.yaml
```

## Adding a New Event

1. Copy COMTRADE files to `samples/comtrade/`:
   - Use the event identifier as the stem: `<event_id>.cfg` + `<event_id>.dat`
2. Copy CSV/Excel files to `samples/csv/` or `samples/excel/`
3. Run the inspector to verify metadata:
   ```
   python tools/inspect_comtrade.py samples/comtrade/<event_id>.cfg
   python tools/inspect_csv_timeseries.py samples/csv/<event_id>.csv
   ```
4. Build the manifest:
   ```
   python tools/build_event_manifest.py --event-id <event_id> \
     --comtrade samples/comtrade/<event_id>.cfg \
     --csv samples/csv/<event_id>.csv \
     --output samples/manifests/<event_id>.yaml
   ```
5. Commit the manifest. The manifest is the persistent record that future
   sessions use — not the raw files (which may be large or confidential).

---

## Token Efficiency Philosophy

Large waveform files are expensive to describe to AI assistants. This directory
exists so that:

- Inspection tools summarize files locally
- Claude reasons from the summary/manifest, not raw binary data
- Manifests are committed as lightweight YAML records

Do NOT paste raw `.dat` binary content or large CSV rows into Claude prompts.
Instead, run `inspect_comtrade.py` / `inspect_csv_timeseries.py` and paste
the output summary.
